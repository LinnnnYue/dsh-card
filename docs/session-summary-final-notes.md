# 视觉精修记录 · v2 → v3-polished

**任务边界**：只做视觉精修。信息条目 12 项、分组方式、图形类型（条形）、文案、板块顺序一律不动。
**方向**：Stripe Press（温润编辑感 × 4/8/16/24/32 间距体系）× Linear（发丝线、display 负字距、强调色 <5%）× Tufte（数据墨水比）。

---

## 一、逐条改动

| # | 改了什么 | 为什么 | 对应原则 |
|---|---|---|---|
| 1 | 字号从 **5 阶**（10.5 / 11 / 11.5 / 12.5 / 13）收敛为 **4 阶**（12 / 14 / 16 / 20） | v2 的 10.5 与 11 只差 0.5px，人眼分辨不出却被当作两级用，层次信号失效 | H2 硬验收；Linear「清晰层级」 |
| 2 | 主标题 20px / 字重 500 / **letter-spacing -0.02em** | 中文字距本就紧，大字号下需要负字距才不显松散；这是 display 级的信号 | Linear `-0.02em` |
| 3 | 间距从 **11 个散值**（3/6/9/10/11/12/13/14/16/18/52）收敛到 **4 档**（8 / 12 / 16 / 24/32） | v2 的 3、6、9、11、13 是无系统的手调值，视觉上表现为「到处差一点」 | Stripe Press 4/8/16/24/32 |
| 4 | 条形 **13px → 8px 高**，两端 **直角 → 2px 圆角** | 13px 实心直角块读起来像「进度条控件」，不是「数据」；8px 是数据条的常见高度，圆角 2px 去掉工业感但保持精确 | Tufte 数据墨水比；Linear radius 克制 |
| 5 | 条形改为 **flex 基线对齐**，四根条统一在 x=76 起跑（实测 76.0/76.0/76.0/76.0） | v2 用 `gap:9px` 串联，标签列 56px 宽但内部有 9px 缝，基线不统一 | H3；「标签列与数据列基线对齐」 |
| 6 | 数值加 `font-variant-numeric: tabular-nums`，且 `min-width:24px` | 等宽数字让 4/8/2/55 四个数字形成一列可扫的竖轴 | Tufte；「数字等宽对齐」 |
| 7 | 结论块：**2px 左色条 + 浅底 + 圆角 → 整条 band 顶部一根 1px 发丝线**，颜色只留在「已完成 / 还差一步」两个标签上 | v2 是「色块套色块」——浅底 + 左色条 + 圆角，三层装饰抢了内容；改成一根发丝线划开两半，层次靠留白与字号区分 | H1 精致度项 8；Linear 发丝线；强调色降占比 |
| 8 | 结论块正文 **13px → 16px 衬线** | 整张卡只有这两句是「结论」，却和正文同尺寸；放大到 16px 建立唯一的信息高点 | 视觉重心 |
| 9 | 教训条：虚线 **1.5px dashed → 1px** `text-decoration: underline dashed`，下沉 4px | v2 的 `border-bottom:1.5px dashed` 画在 12.5px 字上，虚线粗过笔画显得笨重；改为下划线虚线可随字体度量走 | 「虚线装饰线变细」 |
| 10 | 时序序号圆：**描边保持**，连线从「每行 5px 短桩」改为 **`.seq::before` 一根连续导轨**（`--text-muted` @ 40%） | v2 用 `bottom:-1px` 逐行拼接，行高不足时短桩之间断裂；容器级一根线视觉上才「连得上」。用 muted 而非 border，是因为 `--border` 在白底上几乎不可见 | 「发丝线分隔」；工艺质量 |
| 11 | 时序粗体 **accent → text**，强调色只留在序号圆 | 让内容（动词）自己重，而不是靠颜色代替字重；全卡 accent 占比进一步下降 | Linear 强调色 <5% |
| 12 | 所有板块用 **1px `--border` 发丝线**分隔，板块间 16px，组内 8px | v2 靠 14/16/18px 随机留白分隔，没有分割线；加上发丝线后「区块」这件事才成立 | Stripe Press；「间距有节奏」 |
| 13 | 列轴统一：band 与 cols 的 `gap` 都是 **32px**（实测两列左沿 16 / 466 完全对齐） | 精修中发现 band 用 48px、cols 用 32px，两行右列起点差 8px——这是实测才抓到的错位 | 「对齐」；工艺质量 |
| 14 | 列表圆点 **7px → 6px**，`border-radius:1px` | 与 8px 条形形成小号/大号的稳定比例；7px 是奇数，与 8pt 网格不同频 | 4/8 体系 |

## 四、自评与扣分点

**自评 8.6 / 10**

做对的：
- 字号与间距的两套系统真正建立起来了，不是「感觉更整齐」而是 5 阶→4 阶、11 个散值→5 个网格值
- 发现了 v2 里三处只有实测才看得见的错位：条形基线、两列 `gap` 不一致（48 vs 32）、时序短桩断裂
- 结论块的「卡套卡」彻底拆掉，层次靠排版而非色块

扣分：
- **-0.6 留白仍然偏保守**。板块间只有 16px，Stripe Press 的编辑感通常要 24–32px 才有「呼吸」。我为了压住 1400px 高度上限做了妥协，这处是「验收约束」压过「审美直觉」的让步，不是最优解。
- **-0.4 时序导轨的收尾不够讲究**。`.seq::before` 的 `bottom:8px` 是估算值，不是量出来的；严格做法应该让导轨在最后一圆中心处收住并对齐圆边。
- **-0.4 顶部节奏偏平**。标题区（20px 标题 + 12px 元信息 + 24px 后进结论带）三段的间距是 8 / 24，第二跳大了一倍，读起来有点「跳」；理想是 8 / 16 / 24 的递进。

**是否牺牲可读性**：没有。字号整体上调（正文 12.5 → 14，结论 13 → 16），对比度用 `--text` 与 `--text-secondary`，没有为了精致把字做小或做灰。第 6 项「强调色下降」是通过「把颜色换成字重」实现的，不是通过降对比度。
